# PDFs (Formidable PDFs add-on)

Read this when: adding PDF download links to views/pages/emails, generating a PDF of an entry or a whole View, attaching PDFs to email actions, or debugging PDF rendering/permissions. Sources: formidable-pdfs 2.1 plugin code + the official KB (https://formidableforms.com/knowledgebase/pdfs/), verified end-to-end on a live view.

## Requirements

- **Formidable Pro ≥ 5.4.2 is mandatory** (and core Formidable ≥ 5.4.2); the add-on requires a Business license or above
- PHP ≥ 7.1 with the `dom`, `mbstring`, and `gd` extensions
- View-based PDFs additionally need the **Formidable Views** plugin
- PDF engine is a **bundled Dompdf** (`classes/lib/dompdf/`) — all rendering constraints below follow from Dompdf's capabilities
- If requirements aren't met, the plugin loads nothing but admin notices (no shortcode, no hooks)

## The one shortcode: `[frm-pdf]`

The plugin registers exactly one shortcode (handler: `FrmPdfsShortcodeController::frm_pdf_handler`). It outputs an `<a>` link (or bare URL) pointing to a generated PDF.

### Declared attributes (with defaults)

| Att | Default | Meaning |
|---|---|---|
| `id` | `''` | Entry ID. **Auto-injected inside View content** (see below). With `view=`, selects that View's *detail page* entry. |
| `view` | `''` | View ID — render that View as the PDF instead of the entry table |
| `label` | `Download PDF` | Link text. **`label=""` makes the shortcode return the bare URL** instead of a link |
| `title` | `''` | `title` attribute (falls back to label) |
| `class` | `''` | Extra CSS classes; `frm_no_print` is ALWAYS appended (the link hides itself inside generated PDFs) |
| `html_id` | `''` | `id` attribute on the link |
| `target` | `''` | e.g. `"_blank"` |
| `mode` | `view` | `view` = open inline in browser; `download` = force download dialog. (`file` exists but is coerced to `view` in shortcodes — it's only used internally for email attachments) |
| `public` | `''` | `public=1` appends a time-limited access code so logged-out users can download (see Permissions) |
| `output` | `''` | `output="url"` returns the raw URL string (for custom markup) |
| `access_code` | `''` | Explicit access code / gated-content token (normally auto-generated by `public=1`) |
| `orientation` | `portrait` | `portrait` or `landscape` |
| `include_fields` / `exclude_fields` | `''` | Comma-separated field IDs (entry-table PDFs) |
| `include_extras` | `page, section` | Comma list: `page`, `section`, `html`, `admin_only`. **`admin_only` bypasses field-visibility checks — combined with `public=1` it exposes admin-only fields to anyone with the link** |

### Undeclared attributes that also work (pass-through)

Any attribute not in the skip list (`label`, `title`, `class`, `html_id`, `target`, `public`, `output`, `access_code`) is packed into the download URL and re-emitted onto the inner rendering shortcode. Functional and commonly needed:

- `filename` — output filename without `.pdf`; supports Formidable shortcodes: `[form_name]`, `[key]`, `[date format="Y-m-d"]`, field IDs; `{ }` may be used instead of `[ ]`. Result is passed through `sanitize_title()`. Default: `frm-[form_name]-[date]-[key].pdf` (the `frm-` prefix is only added when no custom filename is given)
- `paper_size` — `letter` (default), `legal`, `A4`, …
- `show_pagination` — `1` adds "Page X of Y" footers (styleable via `.frm_pdfs_pagination` CSS)
- `wpautop` — `0` prevents auto-`<p>` wrapping (fixes broken CSS blocks with blank lines)
- `entry_id` — with `view=`, filters the View listing to one entry (different from `id`, see below)
- `source` — name of any shortcode to render (e.g. `source="display-frm-data"`); advanced
- When `view=` is set, any native `display-frm-data` att passes through: `limit`, `page_size`, `order_by`, `order`, `filter`, `drafts`, `get`, `get_value`, `user_id`, `offset`

## How the download URL works

- The URL is `home_url()` + one opaque param: `?frm_data=<urlencoded base64 of the query string>` (always contains `action=frm_entry_pdf`). **Never hand-assemble `frm_data`** — get URLs via `output="url"` or `label=""`, or filter with `frm_pdfs_download_url`.
- Any front-end page load carrying a valid `frm_data` is intercepted at the `wp` hook (priority 1), permission-checked, the PDF is streamed, and PHP exits.
- The admin "Download as PDF" link on the entry page (Entry Actions sidebar) is the same handler called from PHP.

## The three content sources

Dispatch: entry table when neither `view` nor `source` is set; View when `view=` is set; otherwise the `source` shortcode.

1. **Entry table (default)** — `[frm-pdf id=123]` renders the entry's fields as a generated table ("Added on" date + field/value rows, div-based markup tuned for Dompdf). `include_fields`/`exclude_fields`/`include_extras` apply here.
2. **A View** — three distinct behaviors, get this right:
   - `[frm-pdf view=10]` → the **whole View listing** as a PDF (all entries, with before/after content)
   - `[frm-pdf view=10 id=363]` → the View's **detail page** for entry 363 (`id` is mapped to the View's detail param)
   - `[frm-pdf view=10 entry_id=363]` → the View **listing filtered** to entry 363
3. **Any shortcode** — `[frm-pdf source="display-frm-data" id=10 ...]` (legacy/advanced syntax; `view=` is simpler).

## Inside View content: automatic entry ID injection

The plugin filters View content (`frm_display_entry_content` + `frm_replace_content_shortcodes`, priority 20) and appends `id="<current entry>"` to any `[frm-pdf]` **that has no `id` att**. So:

- In a listing row or detail page, a bare `[frm-pdf]` gives each row a link to *that entry's* PDF.
- A whole-View download link (`[frm-pdf view=N ...]`) is safe in the View's **before/after content** — verified: no entry id gets injected there, and the generated link carries `view=N` with an empty `id`.
- The link always carries class `frm_no_print` (`display:none` in the PDF CSS), so a download button inside the View content disappears from the PDF itself. No need to strip it manually.

Verified working example (a menu View with a whole-menu PDF button in `before_content`):

```
[frm-pdf view=10884 label="Download Menu (PDF)" public=1 mode="download" filename="bella-napoli-pizza-menu" class="my-btn-class"]
```

## Permissions & access

No nonces — authorization is capability / ownership / access-code only (`handle_request`):

- **Logged-in**: needs `frm_view_entries` capability OR being the entry's owner (`user_id` match). Whole-View PDFs (no entry) check the capability only — entry ownership can't help there.
- **`public=1`**: appends `access_code=md5(date-based hash + secret)`. Codes are valid for the generation day + 3 previous days (default window 4 days; filter `frm_pdfs_access_code_max_days`). The code is **shareable, not per-user** — anyone with the URL can download while it's valid. After expiry the link 403s; the shortcode regenerates a fresh code on each page render, so links *embedded in pages/views* keep working — only copied/emailed URLs go stale.
- "You are not allowed to view this entry" → the viewer lacks capability/ownership and there's no valid code → add `public=1` (and accept the shareable-link tradeoff).
- The Gated Content form action can wrap PDFs as gated items (`items[].type = "frm_pdf"`, `id` = the `[frm-pdf ...]` shortcode string) with per-entry token binding — separate from `public=1`. See `actions.md` § Gated Content Action.

## Email attachment integration

- Each **email action** has an "Attach PDF of entry to email" toggle (setting key `attach_pdf` in the action's `post_content`) — settable via MCP `create-form-action`/`update-form-action`.
- The attachment is the **entry-table PDF** by default. Customize (e.g. use a View, filename, paper size) with the `frm_pdfs_email_attachment_args` filter — but `mode` is forced to `file` *after* the filter, so don't try to change mode.
- Only the email action integrates with PDFs; no other action type does.
- The temp PDF is written to `get_temp_dir()` and deleted after sending.

## Rendering constraints (Dompdf) — design for these up front

- **Use `<table>` layouts, not flexbox/grid**, for anything that must look right in the PDF. The plugin auto-converts grid Views' CSS grid to `display:table` and strips `frm-responsive-table` from table Views, but hand-written View HTML is on its own. A two-column card = a 2-cell table row. (Verified: table-based menu cards render pixel-perfect.)
- **Inline styles** are the most reliable; the PDF also inherits the form's default Formidable style + `pdf.css.php`.
- Explicit margins/line-height beat margin collapsing — Dompdf can overlap stacked headings that look fine in the browser (verified; fixed by setting explicit `margin`/`line-height` on both elements).
- `page-break-inside:avoid;` on each repeating card prevents cards splitting across pages; force breaks with a `.page_break { page-break-after: always; }` class.
- **Images**: local uploads are read from the filesystem (fast, reliable). External image URLs require `allow_url_fopen` — if it's off they're silently dropped. Prefer media-library URLs. SVGs are converted to data URIs automatically.
- **Remote image URLs must be free of percent-encoded characters.** A hotlinked URL containing `%2C` (encoded commas in the filename) renders in the browser but shows "image not readable or empty" in the PDF — Dompdf's URI encoding mangles already-encoded characters. Plain `[A-Za-z0-9_.-]` filenames work fine remotely. Prefer an image already in the media library, whose local path Dompdf reads straight from disk.
- **`[frm-graph]` does not work in PDFs** — graphs are excluded.
- Avoid emoji/exotic glyphs (Dompdf's bundled fonts lack them); add custom fonts via Google Fonts `<link>` + `frm_pdfs_css` if needed.
- No settings screen exists. There are **no built-in margin, header/footer, or password/encryption options** — use hooks: `frm_pdfs_css` (inject `@page` rules / CSS), `frm_pdfs_export_content` (wrap HTML), `frm_pdfs_before_render`/`frm_pdfs_after_render` (raw Dompdf object), `frm_pdfs_dompdf_args` (constructor options).
- Server limits are raised automatically during render (`set_time_limit(0)`, memory ≥ 256M).

## Hooks quick list

`frm_pdfs_default_shortcode_atts`, `frm_pdfs_shortcode_output`, `frm_pdfs_download_url`, `frm_pdfs_export_content`, `frm_pdfs_export_file_name`, `frm_pdfs_fields_for_export`, `frm_pdfs_show_args`, `frm_pdfs_css`, `frm_pdfs_email_attachment_args`, `frm_pdfs_dompdf_args`, `frm_pdfs_access_code_max_days`, `frm_pdfs_before_render`, `frm_pdfs_after_render`.

## Recipes

```
[frm-pdf]                                            <!-- View row/detail: entry id auto-injected -->
[frm-pdf label="Get PDF" mode="download"]            <!-- force download dialog -->
[frm-pdf public=1]                                   <!-- logged-out visitors, ~4-day shareable code -->
[frm-pdf view=84]                                    <!-- whole View as one PDF -->
[frm-pdf view=84 id=[id]]                            <!-- detail page of current entry, on a page -->
[frm-pdf view=84 orientation="landscape" paper_size="A4" show_pagination=1]
[frm-pdf filename="invoice-[key]" mode="download"]   <!-- custom filename -->
[frm-pdf output="url"]                               <!-- bare URL for custom markup -->
```

## Verification method (no browser download needed)

1. Load the page with Playwright and read the link: `document.querySelector('a.your-class').href` — sanity-check the decoded `frm_data` (base64) contains the expected `view=`/`id=`/`mode=`.
2. `curl -sk "<href>" -D headers.txt -o out.pdf` — expect `200`, `content-type: application/pdf`, `content-disposition: attachment; filename="<name>.pdf"`. With `public=1` this works logged-out (curl has no cookies), proving guest access.
3. Visual check on macOS: `sips -s format png out.pdf --out page1.png` renders page 1 (only page 1); read the PNG.
4. Note: `file out.pdf` may report "0 pages" on Dompdf output — that's a `file`-utility quirk, not a broken PDF; trust the sips render.

## Gotchas

- `[frm-pdf]` with neither `id` nor `view` (outside a View, where nothing is injected) returns an **empty string** — no error.
- `mode="file"` in a shortcode is silently treated as `view`.
- The `id`-att semantics change with context: alone = entry-table entry; with `view=` = detail-page entry. Use `entry_id` for "filter the listing".
- First PDF generation on a modern-PHP site writes a burst of `Dompdf\FrameReflower\*::reflow(): Implicitly marking parameter $block as nullable is deprecated` notices to debug.log — vendored-library noise from the bundled Dompdf, not an error in your work; report as pre-existing-pattern noise in log diffs.
- Public links in *emails* expire (~4 days); links rendered on pages self-refresh their code each render.
